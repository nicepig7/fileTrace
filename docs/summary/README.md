# Trace File 사례 공유

* **제출자**: 나
* **사례명**: AI로 구축한 '코드 연계 지도(TraceFile)'
* **부 제**: 정적 분석 뷰어 개발 및 AI 페어 프로그래밍 노하우 공유

---

### 1. 어떤 업무에? (현재 상황과 프로젝트 시작 동기)

글로벌 금융 모바일 뱅킹 차세대 구축 프로젝트에 참여하며 겪었던 실무적 한계를 극복하기 위해 시작했습니다. 당시 프로젝트는 아래와 같은 3가지 고유의 특수성과 어려움이 있었습니다.

1) 익숙지 않은 모바일 채널계 도메인
- Android(Native), Vue(Hybrid Web), Java(Backend)가 복합적으로 얽혀 있어 전체 시스템의 종단간(End-to-End) 흐름을 파악하기가 매우 까다로웠습니다.

2) MCI 기반 대외계/계정계 중심의 아키텍처
- 은행 채널계 시스템의 특성상 핵심 비즈니스 로직은 서버 자체 연산보다는 MCI를 통해 Core Banking(계정계)이나 외부 솔루션을 호출하는 구조였습니다.
- 즉, "이 모바일 화면/API가 계정계의 어떤 전문을 호출하는가?"를 파악하는 것이 업무 분석의 90% 이상을 차지했습니다.

3) 글로벌 현지 개발자와의 언어 및 문화적 소통 장벽
- 소스코드의 세부 구현 의도나 인터페이스 호출 관계를 확인하기 위해 현지 개발자들에게 구두나 메신저로 매번 묻고 확인하는 과정에서 큰 소통 비용과 딜레이가 발생했습니다.

■ 시작 동기:
"사람이 수백 개의 소스 파일을 일일이 열어보며 쫓아다니지 말고, 소스코드의 연결 고리를 기계적으로 역추적하여 한눈에 보여주는 '인터랙티브 코드 지도'를 만들자"
1인 개발자가 단시간에 이 거대한 툴을 처음부터 다 만들기 어렵기 때문에, AI(Gemini / Antigravity)를 페어 프로그래머로 삼아 프로젝트(TraceFile)를 시작했습니다.

### 2. 무엇을 만들었는가? (구현한 작업과 핵심 기능)

단순한 일회성 분석 스크립트에 그치지 않고, [정적 분석 엔진] + [브라우저 내장 DB 웹 뷰어] + [Jenkins CI/CD 완전 자동화]까지 이어지는 풀스택 플랫폼을 구축했습니다.

1) 백엔드 정적 분석 엔진 (Node.js / npm run build:data)
- 전체 Java 소스를 정규식으로 훑던 초기 단계를 넘어, Java AST(구문 트리) 및 XML 파서를 AI와 함께 구축했습니다.
- BFS 기반 역방향 호출 그래프 알고리즘을 통해 와일드카드 import(.*), 상속 관계, 다중 SQL JOIN 쿼리까지 추적하여 [화면(AOS/Vue) -> API Controller -> Service -> DBIO/MCI]의 종단간 연계를 전수 분석합니다.
- 분석 결과는 수만 건의 대용량 데이터도 수용할 수 있도록 단일 경량 DB 파일(public/data.sqlite)로 압축 적재됩니다.

2) 프론트엔드 대화형 웹 뷰어 (Vue 3 / WASM SQLite)
- 별도의 무거운 WAS/API 서버 없이 완전 정적 웹사이트(report/)로 배포됩니다.
- 브라우저 메모리 상에서 WebAssembly 기반 SQLite(sql.js)를 직접 구동하여, 수만 건의 데이터도 네트워크 지연 없이 브라우저 로컬에서 수 밀리초(ms) 단위 초고속 SQL 쿼리로 실시간 검색 및 트리를 전개합니다.
- 3개 뷰어 제공:
  * API 탐색기 (/api): 모바일 화면부터 백엔드 DB 쿼리/MCI까지 전체 호출 트리 시각화
  * MCI 전문 탐색기 (/mci): 계정계 전문 코드 검색 시 호출 위치 및 연관 화면/API 1초 만에 역추적
  * 테이블 탐색기 (/table): DB 테이블별 CRUD 내역 매핑 및 컬럼 정의서 Excel 다운로드
- 형상관리(Git) 소스코드 딥링크 & Git Blame:
  * 뷰어 내 뱃지 클릭 시 형상관리 저장소(GitLab/GitHub) 원본 소스코드 라인으로 즉시 이동하고, 마우스 호버 시 해당 코드를 작성한 개발자 ID(Git Blame)를 즉시 확인.

3) Jenkins CI/CD 파이프라인을 통한 무인 자동화
- 빌드 노드: 매일 밤(또는 커밋 시) 최신 소스를 Checkout 받아 `npm run build`를 자동 실행.
- 배포 노드: 빌드 산출물(report/)을 사내 Nginx 웹 서버로 자동 전송(Unstash)하여 사내 웹 사이트에 즉각 반영.
- 결과: 개발자가 로컬에서 수동으로 돌릴 필요 없이, 출근 후 사내 브라우저 접속만으로 항상 최신 코드 지도를 열람할 수 있습니다.

### 3. AI와 어떻게 협업했는가? (AI 실전 노하우와 생산성 고민)

이 프로젝트에서 얻은 가장 큰 수확은 "AI와 일하는 방식에 대한 프랙티스"를 정립한 점입니다. 단순 코딩 도우미를 넘어 AI와 극한의 시너지를 내기 위해 아래 4가지 관점에서 치열하게 고민하고 적용했습니다.

1) 역할의 전환: "코더"가 아니라 "도구 제작자(Tool Maker)"로의 AI 활용
- [고민] 수만 줄의 사내 소스코드를 AI 프롬프트에 직접 넣으면 토큰 한계, 환각(Hallucination), 사내 보안 문제가 발생합니다.
- [해결] "AI에게 비즈니스 소스코드를 직접 읽히지 말고, 분석하는 도구(엔진과 대시보드)를 만들게 하자!"
  AI에게는 프레임워크 표준 규칙과 파싱 로직만 작성하게 하고, 대용량 소스코드 분석은 로컬 컴퓨터가 기계적으로 100% 정확하게 수행하도록 역할을 분리했습니다.

2) 컨텍스트 관리: `docs/` 폴더와 `CHANGELOG.md`를 '단일 진실 원천(SSOT)'으로 구축
- [고민] 대화 세션이 길어지거나 새 대화를 시작할 때마다 AI는 이전 설계 맥락을 잊어버리고 엉뚱한 코드를 제안합니다.
- [해결] 프로젝트 내부 `docs/` 폴더에 시스템 아키텍처(architecture.md), 기능 명세(features.md), 레이아웃 설계 원칙 등을 마크다운 문서로 체계화했습니다.
  또한 `CHANGELOG.md`에 매 버전의 핵심 변경 사항을 간결하게 기록해 두었습니다.
  새로운 작업이나 리팩토링 시, 장황하게 배경을 설명하는 대신 "docs/features.md의 규격을 참조해서 X 기능을 구현해줘"라는 짧은 프롬프트만으로 AI가 정확한 프로젝트 맥락 위에서 작업하도록 유도했습니다.

3) 프롬프트 규칙 & AI 친화적 아키텍처 (인지 부하 및 환각 방지)
- [고민] AI에게 "검색창, 필터, 리스트가 있는 화면 전체를 짜줘"라고 하면 CSS flex 깨짐, 스크롤 오류, 상태 꼬임 등 미세 버그가 발생해 디버깅 대화로 수만 토큰을 낭비하게 됩니다.
- [해결] 선언적 얕은 껍데기(Thin Shell) 컴포넌트인 `PageLayout` 패턴을 설계했습니다 (docs/design/page-layout-ai-collaboration.md).
  - 공통 레이아웃(헤더, 사이드바, 외곽 flex 스크롤)은 껍데기 컴포넌트로 완전히 캡슐화.
  - 비즈니스 상태와 액션만 명시적 슬롯(#actions, #default)으로 분리.
  - 결과적으로 개발자가 AI에게 "PageLayout을 사용해서 XxxPage 만들어줘"라는 단 한 줄의 프롬프트만 주어도, AI가 복잡한 CSS를 고민할 필요 없이 오직 '데이터와 UI 컴포넌트'에만 집중하여 오류 없는 코드를 단번에 완성할 수 있었습니다.

4) 다국어 번역 스크립트(helper.js)를 통한 협업 도구 제작
- [고민] 소스코드에 포함된 수천 개가 넘는 다국어(영문/현지어) 전문 명세를 일일이 번역하고 사전을 구축하기에는 인력과 시간이 턱없이 부족했습니다.
- [해결] AI에게 번역 자동화 파이프라인 스크립트를 작성하게 하여, 누락된 명세를 자동 수집(TODO)하고 한국어/영어/베트남어 등 3개국어로 번역하여 캐싱하는 시스템을 단 이틀 만에 구축했습니다. AI가 코드 생성기이자 데이터 정제 파이프라인 구축자로 활약했습니다.

### 4. 어떤 효과가 있었는지? (정량적 / 정성적 성과)

1) 업무 분석 및 온보딩 시간 90% 이상 단축
- (기존) 1개 API의 호출 흐름과 계정계 전문을 파악하기 위해 수십 개 소스 검색 및 개발자 질의로 반나절~하루 소요.
- (개선) 검색창에 키워드 입력 후 1초 만에 End-to-End 전체 흐름 및 형상관리 소스 라인 확인.

2) 언어 장벽을 넘어선 '팩트(Fact) 기반 글로벌 협업'
- 서툰 영어로 긴 설명을 주고받을 필요 없이, 시스템이 보증하는 공식 데이터와 URL 링크 기반 소통으로 커뮤니케이션 미스 및 감정 소모를 제로화했습니다.

3) 영향도 누락 방지로 릴리스 장애 예방
- 계정계 전문 포맷이나 DB 컬럼이 변경될 때, 영향받는 채널계 API와 모바일 화면을 누락 없이 전수 조사할 수 있어 배포 안정성을 대폭 높였습니다.

4) 1인 풀스택 유니콘 생산성 실현
- 백엔드 AST 파서(Node.js), 데이터베이스(SQLite), 프론트엔드(Vue 3), 반응형 디자인 시스템(Vanilla SCSS), 배포 파이프라인(Jenkins)까지 1인이 단 2달 만에 프로덕션 수준으로 구축 완료했습니다.

### 5. 다른 팀 / 타 프로젝트 확산 가능성 (확장 방안)

본 도구와 구축 방법론은 사내 다른 금융 시스템 및 타 부서 프로젝트에도 즉시 이식 가능합니다.

1) 타 프로젝트 확장 검증
- 초기 MBW(모바일 뱅킹) 단일 프로젝트로 시작했으나, 동일한 파이프라인을 확장하여 현재는 ADM(관리자 포털) 및 COR(코어 모바일) 프로젝트까지 성공적으로 추가 연동하여 서비스 중입니다.

2) 프레임워크 표준 규칙만 추가하면 타 시스템 적용 가능
- Java / Spring / MyBatis 기반 프로젝트라면, 해당 시스템의 인터페이스 호출 규칙(MCI 표준 코드 포맷 등)과 DB Mapper 구조만 설정 파일에 매핑해주면 즉시 정적 분석 리포트를 생성할 수 있습니다.

3) 사내 소스코드 보안 문제 완전 해소 (온프레미스 폐쇄망 동작)
- 본 도구는 사내 전체 소스코드를 외부 AI API로 전송하지 않습니다.
- AI에게는 "분석기 프로그램 코드"만 작성받았고, 실제 소스코드 파싱과 DB 생성은 사내 폐쇄망 빌드 머신(Jenkins)에서 100% 온프레미스로 안전하게 수행되므로 사내 보안 규정을 완벽하게 준수하며 전사 확산이 가능합니다.
